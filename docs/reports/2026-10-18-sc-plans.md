# The single-crystal page's changes as plans

Branch `claude/sc-plans`, stacked on `claude/pdf-plans` (#70), 2026-10-18.
Plan: [AGENT_PLAN.md](../AGENT_PLAN.md), 3.1. The second page of the
architecture review's #4, second half: the shape #70 set on the PDF page,
applied to the single-crystal page's 19 change tools.

The single-crystal page had the three switches the PDF page had: a no-op
(`singleCrystalNoOp`), the card's line (`describeSingleCrystalChange`) and the
change (`changeSingleCrystal`), about 340 lines in all. Most tools worked
out the same thing in two or three of them: the twin laws after the change,
the weights, the restraints, the riding rules, the merged data set, the
omissions.

## What changed, and why

| Change | What it answers |
| --- | --- |
| `SC_PLANS` (`scTools.ts`): one plan per change tool of the page, each on its tool's input as the schema parses it. A tool works out what it would do once, and the card's line and the change both use it. The compiler holds the table to the page's change tools, and a test does too | Three switches, the same work done in two or three of them |
| `set_free`, `refine`, `reset_parameters` and `go_to_step` are the shared plans (pages/plans.ts). The page's `refine` gives its own card line (F² against the reflections fitted) and its notes after a fit (free hydrogens, a listing's extinction) | The page's own copies of the four |
| A change that cannot run is refused before its card: a reflection to keep that is not on the failed list, and a refinement with nothing free. The other checks were already made before the card, in the no-op | The user approved a card for a change that then failed |
| Riding hydrogens still check, after the change, that some hydrogen rides, with the note the page returns. That note exists only once the change is made | Moving that check before the card would lose its note |

## Evidence

- **The plans say what the switches said.** For 42 calls on six pages (252
  in all), the plan gave the same card line, the same reason for doing
  nothing, or the same error as the old no-op and card line. The pages:
  corundum, the chiral complex measured at two equivalents, an organic
  crystal, a twinned crystal, a disordered one, a hydride. The calls cover
  all 19 tools, both ways where a tool has two (on and off, add and remove,
  set and clear), and the inputs that refuse. The only differences are the
  two checks that now come before the card.
- **Before the card** (`agent/pages/plans.test.ts`). On the base branch, a
  reflection kept that was never on the failed list, and a refinement with
  every parameter fixed, each showed a card and failed once approved. Now
  both are refused before their card with the same message; only the
  `set_free` between them asks.
- **In the browser**, the three committed demo replays, the corundum
  crystal's refinement among them, gave the same drawer text as before, with
  no page error.
- **Nothing else changed.** The text the model reads is the snapshot's. The
  single-crystal tool tests, the agent scenarios (sc1b, sc2b, sc3a), the
  evals and replays, and the executor pass unchanged.

## What changes for users

On the single-crystal page, as on the PDF page, a change the Agent proposes
that cannot run is refused before you are asked to approve it.
