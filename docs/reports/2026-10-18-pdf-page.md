# The PDF page's operations in one module

Pull request [#66](https://github.com/drthyang/web-refinement/pull/66),
branch `claude/pdf-page`, 2026-10-18. Plan: [AGENT_PLAN.md](../AGENT_PLAN.md),
1.2. The second change of the architecture review's first candidate (the PDF
and single-crystal page modules), after
[the single-crystal page](./2026-10-18-single-crystal-page.md).

The PDF page had two implementations: the workbench's React state and
handlers, and a hand-written copy in the Agent's headless page
(`testSupport/agentHeadless.ts`) that the PDF evals and the scripted replays ran
on. The copy did much less than the page, and in the workbench the parameter
rows followed each change of the model one render late: a spec memo, an effect
that rebuilt the rows after the fact, a fallback for the render in between,
and refs to drop a fit that landed after the spec changed. Both now call one
module, and each change returns the page with its rows already rebuilt.

## What changed, and why

| Change | What it answers |
| --- | --- |
| `app/pdfPage.ts`: the page as a value (`PdfPageModel`: the structure, the extra phases and the G(r) as loaded, a demo's preset, the position parameterization and mode set, the ADP switch, the spin model, the rows, the last fit, the window, the boxcar plan and scan, the posterior run), what it derives read from `pageView` (the structure fitted, the spec, the curves, Rw), and Refine, Prefit / Escape minimum, the boxcar scan, the posterior, the probe and the moment fit as requests to the compute client | One implementation of what the page does, which both adapters call |
| Every change of the spec returns the next page with its rows rebuilt by one function holding the old effect's three rules: a switch between coordinates and mode amplitudes re-seeds the positions from the current geometry; an activation keeps its starting kick and carries only the rows that do not depend on the setting; a new spin model replaces the moment rows. A change the spec does not see (the mode toggle on a multi-phase page, a spin model on X-ray data) keeps the rows and the fit | The rows followed the spec one render late, through an effect, a fallback (`activeParams`) and refs |
| A fit, scan or posterior run carries the spec it ran on; one that lands after the spec changed is dropped (`landsOn`), as before, in one place | Three copies of the staleness check, against a ref |
| The phase scale is seeded only when the rows are built afresh (a new structure, data or phases) | It was computed (a full G(r)) at every change of the spec, then overwritten by the carried value |
| The workbench holds the page in one `useState`. View state (the tab, the overlays, the live curve, progress, the subgroup trees, the magnetic page's snapshot) stays in React | Ten `useState`s and the rebuild machinery |
| The headless page is the GaTa₄Se₈ demo as the app opens it (its converged values as value and initial value), run through the module and the app's compute client, opening on a 1.5–6 Å window passed as the app passes the demo's own | The copy refined 4 iterations (the app 30), returned "cancelled" for Prefit, had no posterior, refined 2 iterations per boxcar box (the app 20), only logged Reset, seeded an ADP switch from the ADPs as loaded, and `go_to_step` left it as it was |
| A reopened project keeps its boxcar scan | An effect cleared the scan on mount, so a saved scan never came back (and the report of a reopened project had none) |
| An ADP switch on a multi-phase page keeps the rows by id | The rows were built afresh: every value back to the spec's default, the scale re-seeded, the fit lost |
| An ADP switch seeds the new rows from the ADPs as refined, also when switching back to the model a demo or a reopened project opened with | Switching back restored the demo's (or the saved) values for those rows instead |

The Agent's `PdfAgentPort` is unchanged.

## Evidence

- **Tests that fail without the change** (`app/pdfPage.test.ts`, through the
  headless page): its requests are the app's (Refine 30 iterations, Prefit 25,
  20 per box, the posterior, all on the page's window); Reset puts the values
  back and clears the fit; an ADP switch seeds B from the refined U; and
  `go_to_step` puts back the step's window, ADP model, rows and fit. All three
  failed on the old copy ("cancelled", B from the loaded U, the window left
  where it was) and pass now.
- **Tests that pin the module**: the switch to mode amplitudes and back leaves
  Rw unchanged (to 9 decimals) and the position value where it was; an
  activation's mode starts free at 0.05 Å with the scale carried; an ADP
  switch back to the demo's own model seeds U from the refined B, and a
  multi-phase ADP switch keeps the scale (the old behaviour of these two, the
  demo's values restored and every row rebuilt, is read from the old spec memo
  and effect, which no test could reach); a fit that lands after the
  parameterization changed is dropped; a new spin model's moment rows replace
  the old ones (same id, new value) while the nuclear rows carry, an
  incommensurate model is refused, and a spin model on X-ray data leaves the
  rows and the fit alone; a page with a window, mode amplitudes, an ADP switch,
  a fit and a boxcar scan, saved to JSON and reopened, gives back every
  setting, every row, the fit, the scan and Rw. After every change the rows are
  the spec's.
- **One existing test changed**: an executor test used the old copy's Prefit,
  which always returned "cancelled", to check that the executor passes on why
  a run did not finish. It now states the cancelled run itself.
- **The app behaves as on `main`, apart from the fixes.** Both builds were
  driven in a browser (Playwright, Chromium) on the GaTa₄Se₈ demo, the page's
  text compared after each step with every parameter group expanded: load,
  Refine, Escape minimum, isotropic ADPs, Refine, mode amplitudes, Refine, a
  boxcar scan, Save project and Open project, the Boxcar view, Reset; then the
  scripted `pdf-local-geometry` Agent replay (a boxcar scan with the Ta shell
  per box, and the report). Identical at every step, timings aside, except the
  reopened project's Boxcar view: on `main` the scan was gone (no Export CSV,
  the "run the scan" prompt), here its 25 boxes are back.
- **The PDF evals stay short**: the PDF tests and scripted evals take 12.0 s
  of test time against 6.8 s on `main`, the slowest scenario 2.8 s.

## What changes for users

- **A reopened project keeps its boxcar scan**, and its report shows it.
- **On a multi-phase page, switching the ADP model keeps the fit.**
- **Switching the ADP model back** to the one the page opened with seeds the
  rows from the ADPs as refined, as it does in the other direction.
- **For the Agent**, on the app's page: nothing. On the headless page (the
  evals): the app's fits, Prefit and Escape minimum, the posterior, Reset and
  `go_to_step` work; a boxcar box refines 20 iterations.

## What it means for the validation

No validation case is a PDF, so arm A's pinned results and the validation set
do not move. The PDF eval scenarios now run on the app's own page operations,
as the powder and single-crystal ones do: plan item 1.2 is done for every page.
