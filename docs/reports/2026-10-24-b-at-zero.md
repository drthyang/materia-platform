# A B that refines to 0: ranked, warned options, and `apply_adp_proposal` by mode

Pull request [#105](https://github.com/drthyang/materia-platform/pull/105),
branch `claude/b-at-zero` (`bd8c2b4`, revision 2 `e357221`, `main` merged
in at `d1f38e7`), from `claude/materia-backlog` at `23c1d88`, 2026-10-24. Backlog
item M10: an isotropic B (or U_iso) that refines to its lower bound at 0
should get a warned, sourced proposal, never a silent change.

## What was wrong

Every isotropic B row has a hard lower bound `min: 0` (`max: 10`) on all three
pages: powder and PDF through `buildStructureSpec`, single crystal in
`singleCrystalRefinement.ts`. The LM engine clamps each trial step into the
bounds and lists a parameter that ends on one in `atBounds`. Read in the code
before any change, a B that reached 0 got:

| Where | Before |
| --- | --- |
| `assess_refinement` | An `at-bound` finding, critical for an ADP, with a per-page reading (powder: over-damped high-angle intensity; PDF: correlated motion; single crystal: extinction or absorption). No value or tie proposed |
| `refine`, `get_state` | The ids in `lastRefinement.atBounds` only |
| Parameter panel | "⚠ at bound" in the Result footer |
| HTML report | Nothing: its details list status, χ², R, null directions and strong correlations |
| `physicalFindings` | Only a *negative* B is flagged, so a B at exactly 0 raised nothing |

The user was left to choose a tie or a held value with no help, and the
report did not say a B had been held.

What a proposal can draw on was checked too. The loaded structure stays on
the session, so its per-site B (a CIF's U_iso read as B = 8π²U) is available
as a reference. The code has no temperature model for B, the models carry no
measurement temperature, and the repository holds no citable table of typical
B by element and temperature: the only figures are an uncited "0.3–1 Å²" in
the PDF zero-ADP warning and the U *limits* of `structureChecks.ts`.

## What changed

**The options** (`core/diagnostics/zeroAdp.ts`, new). For each free B row the
last fit left on its **min** bound, `zeroAdpProposals` lists ranked options,
each with an id, a label, its source and, where needed, a caution:

1. **Preferred: `tie:<row>` to a site of the same element** that refined
   sensibly: free, off every bound, positive and at least 2 esd from 0. The
   best-determined one comes first; other same-element sites follow as
   alternatives, and a different oxidation state gets a caution.
2. **Alternatives: `tie:<row>` to another cation of the same coordination**
   (as many of the same ligands within the coordination shell). Each is
   labelled with both species, for example "same coordination (6 O),
   different cation (W⁶⁺ vs Cr³⁺)", with the caution "a different cation
   (…): check it is physically sensible". They are shown even when a
   same-element tie exists.
3. **Alternative: `start`, the starting structure's B** for that site, held
   fixed and used as it stands, with no temperature adjustment. Listed
   whenever the structure gives a positive value.

Partners are searched in the same phase only. The same-element tie is
preferred, not a hard rule: the owner's decision (revision 2) was that it is
the best choice but will not fit most cases, so the alternatives stay visible
and the choice stays with the user.

**Rule C, a documented typical B, proposes nothing.** With no option above,
the warning says why (no sensible partner, no reference B, no documented
table) and offers nothing to apply. No arbitrary floor is used anywhere.
Building rule C needs a cited source added under `docs/` with a generator, as
for the scattering tables.

**Nothing changes until someone chooses.** Applied, an option is an ordinary
user tie (`withEqualTies`) or a fixed row at the value, a History step ("B at
0: tie B_O2 = B_O1 …"), and undone by Release, ⌘Z, `tie_parameters release`,
`set_free` or `go_to_step`. A fix counts only while its row still carries it:
retyping, freeing or re-tying the row drops the record.

| Change | Where |
| --- | --- |
| The options, the apply step and the fix record, with the texts for History and the report | `core/diagnostics/zeroAdp.ts` |
| The at-bound finding of a B on its lower bound carries the options (`evidence.options`); each fix in force is a note | `core/diagnostics/assessment.ts` |
| The ⚠ **B at its lower bound** notice over the parameter list: the atom, the B it reached, one Apply per option, Release for a fix | `app/ui/ZeroAdpNotice.tsx`, `ParameterPanel.tsx`, `PowderWorkbench.tsx`, `powderPage.ts` |
| The report's warnings list each fix in force and each B left at 0, under "Limitations" in HTML and Markdown | `app/reportInputs.ts`, `core/export/report.ts`, `reportMarkdown.ts` |
| `zeroAdpFixes` saved beside the rows (active fixes only), validated; a file without it opens unchanged | `core/project/types.ts`, `validate.ts`, `app/projectIo.ts` |
| `get_state.bAtZero` (id, rank, tie or value, label, caution); `refine`'s checks carry the full warning | `agent/powderTools.ts` |
| The new tool `apply_adp_proposal`, its card options and the drawer's choice buttons | `agent/tools.ts`, `agent/cardOptions.ts`, `agent/executor.ts`, `agent/ui/AgentDrawer.tsx` |

### `apply_adp_proposal`, by mode

Input `choose: [{parameter, option, reason?}]`. `option` must match
`^(tie:…|start)$` in the schema and be one of that row's offered ids in the
plan; otherwise the call is refused with the row's list. The Agent cannot
name a partner or a value outside the app's options. A cross-element tie
needs a `reason`. The tool text tells the model to prefer the same-element
tie, to take a cross-element one only when physically sensible, and, in
doubt, to take `start` or leave the B and report it.

- **Ask first:** the card shows every option with the Agent's pick
  preselected (★), drawn with the drawer's choice buttons. The user picks on
  the card: their pick is what is applied, which may be another option than
  the Agent's. Decline applies nothing.
- **Auto:** no card; the Agent's pick is applied and recorded as the Agent's
  choice in auto mode everywhere it shows: the result (`applied[].chosenBy`,
  `reason`, `notTaken`), the History label, the notice and the report ("Chosen
  by the Agent in auto mode, without a card … Not taken: …").

Revision 1 had the tool always ask, with the model choosing only which rows;
revision 2 is final.

**Approved during the validation freeze.** The tool changes the model-visible
tool list of both arms before the freeze (docs/AGENT_PLAN.md, phase 6). The
owner decided to add it all the same: "I kind of want to keep it but provide
users to select what to do when it is in the interactive mode. So the agent
can judge it while in auto mode." It is in-app only.

## Evidence

The ten cases and their criteria were written before the code.

- **A synthetic case with a known truth.** Cr₂WO₆ (P4₂/mnm) simulated for a
  λ = 2.4067 Å neutron diffractometer with B(O1) = B(O2) = 0.6 Å² at low
  counts, the scale, background and both O B's free. Noise draw 17: B(O1)
  rails to 0 while B(O2) refines to 0.63(28) Å². The preferred option is the
  tie to B(O2); applied and refined again, the common B(O) is 0.37(20) Å²
  against the truth 0.6, within 1.2 esd and off every bound. Draw 30: B(O1)
  at 0 with B(O2) 0.38(28) Å², under 2 esd, so no tie is offered and the
  option is `start`, held at 0.600 Å² with its source.
- **Ranked options** (unit): O2 → O1 is preferred; W1 → Cr1 (both with 6 O)
  is only a labelled alternative beside `start`, with the cross-cation
  caution. A CIF without B and no partner gives no option (rule C).
- **Never silent:** after `refine` the row stays free at 0; computing the
  options changes no row; a declined card changes nothing.
- **By mode:** ask first, keeping the Agent's pick applies it; picking
  `start` instead applies `start`, not the tie; Decline applies nothing. Auto
  applies the Agent's pick and records it, with its reason and the options
  not taken, in the result, the fix, the notice, the report and `get_state`.
  An id not offered is refused by the plan with the row's list, a non-id by
  the schema, and a cross-element tie without a reason is refused.
- **Override and undo:** release, `set_free` and a typed value each take a fix
  out of force and drop its record; `go_to_step` back restores the free row
  with no record; a later user tie of the same pair is not claimed as a fix.
- **No B at 0:** no option, no warning, no `bAtZero`, and the tool refuses.
- **Saved projects:** a file without `zeroAdpFixes` opens to the identical
  session and is saved again without it; an applied fix round-trips as a user
  tie plus its record; a malformed record is refused by path.
- **The owner's dataset** (data-gated, local only): the benchmark's B-at-0
  criterion is unchanged and still recorded as not met, read on the fit as
  refined with nothing applied. New data-gated cases check that each B on its
  bound gets a warned proposal, that the oxygen site's first option is the
  preferred same-element tie, and that the tungsten site, having no other
  site of its element, gets only labelled alternatives. Applying options and
  refining again is logged as an observation; which options to apply is left
  to the user.

## What changes for users

A powder B that refines to 0 now shows a notice over the parameter list with
ranked options, each with its source and its own Apply, and the report lists
any B held or tied this way, or left at 0, under Limitations. The Agent sees
the options in `get_state`, `refine`'s checks and `assess_refinement`, and
can propose one with `apply_adp_proposal`: asking first, the user picks on
its card; in auto mode its pick is applied and recorded as its own. Projects
gain an optional `zeroAdpFixes` field; files without it open unchanged.

## What it means for the validation

Arm A presses no Apply, and the Validation tab's checks are unchanged, so
its pinned results do not move (the pin test passes). The benchmark criterion
is read on the unapplied fit. Both arms' model text
changes in one place, the new `apply_adp_proposal` section (description and
input schema); the snapshots were regenerated and differ from `main` only
there. Arms B and C can now act on a B at 0 through the tool, which the
owner accepted before the freeze.

## Not done

- **Powder page only.** Single crystal has the same bound and `atBounds`
  path, and an isotropic B at 0 would fit the rule, but needs a held-value
  setter on the SC port, the notice on its workbench and the SC report; its
  at-bound reading is unchanged. A non-positive-definite U tensor has no "B
  at 0" (the remedy is ISOR/SIMU or isotropic) and stays a hard flag.
- **PDF not covered.** A U at 0 first means a missing correlated-motion term
  (δ1/δ2), and the PDF page has no user ties; the existing reading stands.
- **MCP proposals not exposed.** The core `assess_refinement` accepts the
  options, but the MCP schema does not pass them: MCP callers supply no
  bindings or structures to compute them.
- **Anisotropic → isotropic edge case.** Switching the ADP model bakes the
  refined ADPs into the session's structure, so after an aniso → iso round
  trip the `start` option is the value baked at the switch, not the CIF's,
  and its label overstates its provenance.
- **Rule C** waits on a citable B table.
- For the owner: the proposed skill wording for `my-rietveld-workflow` and
  `bayesian-check` is recorded but not applied (the skills are the owner's
  text).
