# A call log for the evidence gate

Branch `claude/call-log`, stacked on [#67](https://github.com/drthyang/web-refinement/pull/67),
2026-10-18. Plan: [AGENT_PLAN.md](../AGENT_PLAN.md), 3.2. The second candidate
of the architecture review in the user's order (the page adapter, then this),
built as the user answered its five questions.

Before the chat lets a final answer stand, the evidence gate
(`agent/evidence.ts`) checks that what the answer concludes was checked in this
message. On the PDF page, local against average needs a boxcar scan. On the
single crystal, a word on the hand needs the absolute-structure reading of the
fit as it stands. On any page, a grade of a fit refined in this message needs
its assessment. The gate knew only the names of the tools that had run, and a
list of six that "change the fit" (`REFITS`). So it judged a call by its name,
not by what it came to.

## What changed, and why

| Change | What it answers |
| --- | --- |
| The executor says, for every change it makes, whether the fit on screen is another one after it (`ToolOutcome.fitChanged`): a refinement's result, a change that cleared the fit, a History step's fit put back. A call that changed nothing (refused, declined, a no-op, a read) does not set it | The gate had no way to know whether a call changed the fit |
| The chat keeps the message's calls as a log: each call's name, its status and `fitChanged` (`CallRecord`), where it kept the bare names | The gate read names only |
| The rules read the log. A reading (`assess_refinement`, `write_report`, `diagnose_fit`) or a boxcar scan counts only when it answered (status ok), and a reading only when taken after the last change of the fit | A refused or declined refinement counted as a refit; a refused, declined or failed scan, or a failed assessment, counted as evidence |
| The fit-grade rule follows any change of the fit in the message, not only `refine` (the user's Q3) | A grade right after a change that cleared the fit (the weights, the extinction model) went unchecked |
| `REFITS` is gone (Q4) | Six names. Six single-crystal changes that clear the fit were not among them: the radiation, the riding hydrogens, the restraints, the merge, the extinction model and the ADP model |
| The context pruning still reads the results' text (Q5): it is correct, and a conversation restored from storage has no statuses | Nothing to fix there |

No text the model reads changed: the nudges and notices are as they were, and
only when they fire changed.

## Evidence

- **Nine cases the old gate got wrong** (`agent/evidence.test.ts`), each run
  through the old, name-based gate first:

  | Calls in the message, then the answer | Old gate | Now |
  | --- | --- | --- |
  | assess, a refused refine, then a grade | sent back | stands |
  | assess, a declined refine, then a grade | sent back | stands |
  | assess, a declined `invert_structure`, then a word on the hand | sent back | stands |
  | assess, `set_extinction_model` (clears the fit), then a word on the hand | stands | sent back |
  | assess, `set_weighting` (clears the fit), then a grade | stands | sent back |
  | assess, `go_to_step` to a step with the same fit, then a word on the hand | sent back | stands |
  | a declined boxcar scan, then local against average | stands | sent back |
  | a failed boxcar scan, then local against average | stands | sent back |
  | a refine, a failed assessment, then a grade | stands | sent back |

  The existing cases (a scan that ran, a reading after the refinement,
  nothing refined, a rule fired once) read the same as before.
- **Through the chat, end to end** (the real chat loop, executor and Mn₃Ga
  page, a scripted model). The model refines, assesses, frees the Mn occupancy
  bare (the firm rule refuses the next refinement), then grades the fit. On
  the old gate the answer was sent back as "a fit refined since its last
  assessment". Now it stands.
- **The executor's `fitChanged`** (`agent/stop.test.ts`):
  - a refinement that ran sets it; a refused or declined one, a free set and
    a read do not;
  - on the single crystal, the weights after a fit set it (the fit is
    cleared).
- **In the browser**, a temporary replay (not committed) ran on dev servers of
  `main` and of this branch, one at a time, on the Mn₃Ga TOF demo. It
  refines, assesses, frees the Mn occupancy, and the refinement is refused
  ("Not run: p0_occ_Mn1, p1_occ_Mn1 free with no tie"). The answer then grades
  the fit "fair", as the engine does. On `main` the drawer sent it back: "The
  answer graded a fit refined since its last assessment; the app asked for the
  assessment first". Here it stands. Neither build had a page error.

## What changes for users

- An answer that grades the fit, or speaks of the hand, after a refinement
  that was refused or declined is no longer sent back for a fresh assessment
  of a fit that did not change.
- An answer that grades the fit, or speaks of the hand, after a change that
  cleared the fit (the weights, the extinction model, the radiation, and the
  others above) is sent back to assess first. Changes that keep the fit (the
  resolution, the omissions, the OMIT filter, a free set) do not count. So is a local-structure answer
  whose boxcar scan did not run.

## What it means for the validation

The gate fires on a run's final answers, so where it sends an answer back
changes. It no longer fires after a refusal, and fires after a change that
cleared the fit. The text it sends is the same, and so is everything else
the model reads.
